## 1. 목적·범위

### 1.1 4M에서 Material의 위치

| 축 | 묻는 것 | 이 기준이 다루는 범위 |
|---|---|---|
| **Material** | **무엇으로 만드는가 / 무엇을 투입했는가** | **전부 (이 문서)** |
| Method | 어떤 순서·조건으로 만드는가 (BOP·공정) | 연결 키만: `processes.id` |
| Machine | 어디서 만드는가 (설비) | 연결 키만: `equipments.op` → 공정 → 자재 |
| Man | 누가 했는가 | 연결 키만: `production_records.user_id` |

Material 은 4M 중 **유일하게 스스로 트리를 이루는 축**이다. 설비·사람·공정은 목록이지만, 자재는 자재로 만들어진다. 그래서 모자관계가 선택이 아니라 전제다.

### 1.2 다루는 것

1. 품목 분류 체계 (Material Class)
2. 품목 마스터 (완성품·서브어셈블리·단품·원자재·부자재·포장재를 **한 테이블**로)
3. 제품 구조 BOM (부모-자식, 유효일자, 대체품, 스크랩률·수량 기준, 소요량·단위)
4. BOM ↔ BOP 연결 (투입 지점·산출물·진행 상태·백플러시)
5. 로트/서브로트·계보·배치 (추적성)
6. 단위와 환산
7. 코드 체계·품목 생애주기·변경 관리(ECO)
8. 추적 단위 정책 (로트/시리얼/무관리)
9. **기준 쿼리** (전개·역전개·합계·공정별 소요·로트 추적) — v1.0 신설

### 1.3 다루지 않는 것 (명시적 제외)

| 제외 | 이유 |
|---|---|
| 재고 수량·창고·로케이션 | 재고는 자재 기준의 **결과**다. 기준이 서기 전에 재고를 설계하면 잘못된 기준이 굳는다. 3단계 이후 별도 문서. |
| 구매·발주·입고 검사 | ERP 영역. 이 기준은 입고 로트가 **생긴 다음**부터 다룬다. |
| 원가 계산 | xlsx 단가는 `item.std_cost` 에 보존만. **전개 합산에 쓰지 않는다** — 04시트 합계는 `SC-1010` 과 그 원소재 `SC-1011` 을 둘 다 더한 값이다(노하린 V12-9). |
| 설비·사람·공정 마스터 | 이미 있다. 키로만 연결한다. |
| 게임 화면의 새 기능 | 이벤트 규격(운영규약 7)을 지킨다. 화면은 §10 범위로 한정. |
| 로트 수량 차감 트랜잭션 | 분할·투입 시 `mat_lot.qty` 차감은 3단계 서비스 계층. 이 문서는 **규칙(D-17)과 감사 뷰**까지. |

## 2. 참조 표준·사례 — 채택과 제외

| 표준·사례 | 핵심 개념 | 채택 | 제외·보류 | 이유 |
|---|---|---|---|---|
| **ISA-95 / IEC 62264 Part 2** | Material Class → Definition → Lot → Sublot | 4계층 **전부 채택**. 이 문서의 뼈대 | Material Test Spec, Capability | QMS 영역. 과하다 |
| ISA-95 | Class 의 자기참조 계층 | 채택 — `mat_class.parent_class_id`, 품목은 말단에만(R-14) | — | 분류 트리가 이것 하나로 해결된다 |
| ISA-95 | Definition Property (속성 자유 확장) | 보류 (2단계) | — | `item.spec` 자유 텍스트로 충분 |
| **ISA-88** | 원재료 / 중간재 / 최종재, **배치** | 중간재 개념 채택(`SC-1010P`) · **배치 개념 v1.0 채택** — `proc_batch`/`proc_batch_lot` | Recipe 계층(Procedure/Unit Procedure/Operation/Phase) | OP-A80·A90 이 30 ea 배치 공정이라 "이 배치의 30대" 를 묶는 최소 단위만 도입(R-23). 레시피 계층은 이산 조립 라인에 값이 없다 |
| **ISO 22400** | Scrap ratio, Material loss | `scrap_pct` + **`qty_basis`(NET/GROSS)** 입력값 정의 | 지표 산출·대시보드 | 지표는 서지안 소관. 순소요/실소요 두 값을 뷰가 함께 낸다 |
| **GS1** | GTIN(외부)·로트·SSCC 를 사내 코드와 분리 | 분리 원칙 채택 — `item.pn` ≠ `item.gtin` | 실제 발급·바코드 | 거래처 요구 없음. 컬럼만 비워 둔다 |
| **IATF 16949 / AIAG** | 정·역방향 추적, 변경 시 승인, 불량 범위 특정 | 계보 양방향 + 추적 단위 정책 + ECO | PPAP·APQP | 사내 시스템. 고객 승인 절차는 대상 아님 |
| **ERP BOM 관행** | 헤더/라인, 유효일자, 대체품, 팬텀, where-used | 전부 채택 | 다중 플랜트, 대체 BOM 다수 | `alt_no` 컬럼만 두고 `'00'` 고정 |
| ERP 관행 | 백플러시 | 채택 (`issue_method`) + **방식별 계보 생성 규칙**(§4.5) | 역백플러시 자동화 | 취소·정정은 수기 |
| SQLite 관행 | 제약은 CHECK/FK/UNIQUE, 식은 인덱스에만, 트리거는 `IF NOT EXISTS` | 채택 | — | 노하린 D-19: 제약에 식을 못 쓴다. 트리거 RAISE 는 리터럴만(R-19 보류 사유) |

**원칙**: 표준은 이름을 빌리되, 우리 데이터가 쓰지 않는 계층은 넣지 않는다. BLDC 라인은 품목 60종·레벨 최대 5단(L0~L4). ISA-95 4계층이면 충분하고 남는다.

## 3. 트리 설계 — 세 개의 축

| 축 | 질문 | 부모-자식의 뜻 | 테이블 |
|---|---|---|---|
| ① 품목 분류 | 이건 **어떤 종류**인가 | 상위 분류 ⊃ 하위 분류 | `mat_class` (자기참조) |
| ② 제품 구조 BOM | 이건 **무엇으로** 만드는가 | 부모 1개를 만들려면 자식 n개가 든다 | `bom_header` + `bom_line` |
| ③ 로트 계보 | 이 물건은 **어디서 온** 물건인가 | 부모 로트가 분할·투입되어 자식 로트가 됐다 | `mat_lot` (자기참조) + `lot_genealogy` + `proc_batch` |

### 3.1 축 ① — 품목 분류 트리 (Material Class)

자기참조 1테이블. **품목은 반드시 말단(leaf) 분류 하나에만 속한다**(트리거 R-14). 24행 = 최상위 6 + 말단 18. 배정은 `cleansing-v1.json` `mat_class`·`items`.

**규모** 품목 **60** = 완성품 1 + 현행 고유 P/N 56 + 신규 3. BOM 헤더 **11**, 라인 **59**, 최대 깊이 **L4**. 노드 60 − 간선 59 = **1** → 정확히 트리. 라인 59 = 연결 46 + 미배정 10 + 팬텀 3.

**읽는 법**
1. 레벨은 깊이이지 유형이 아니다. `FS-7010` 은 L1 이지만 단품(`item_type='PT'`).
2. 소요량은 "부모 `base_qty` 당" 이다. `SC-1011 0.85 kg` 은 `SC-1010P` **80매당**. 완성품당 값은 저장하지 않고 뷰 `v_bom_line_qpp` 가 계산한다(0.85 정확, 오차 0 — 곱셈 먼저 나눗셈 마지막).
3. 팬텀은 구조에 있고 재고·로트·IN·OUT 에 없다. 수량 경로에는 그대로 참여한다(`qty_per` 1).
4. `(추정)` 3건은 08시트가 부모 4개를 한 칸에 적어 행별 부모를 알 수 없는 것이다. P/N 접두로 붙였고 `bom_line.note` 에 "부모 추정" 을 남겼다(V12-1 반영).

### 3.3 축 ③ — 로트 / 서브로트 / 배치 (추적성)

```
[입고] LOT-SC1011-260912-A   SC-1011 코일 1본  qty_init 850.000 kg  공급사 POSCO 밀시트 MS-8842
   │  분할 → 원로트 qty 차감 (D-17)                      qty 849.150 kg
   └─ SUB-SC1011-A-001  SUBLOT  0.850 kg  parent_lot_id=위  ──▶ 투입 OP-A10 (qty_consumed 0.85 kg, 실투입)
          └─◀ 산출 LOT-SC1010P-260912-0007  SC-1010P 80 매        state_pm_id = OP-A10 OUT(is_final)
                 └──▶ OP-A20 ──◀ LOT-SC1010-260912-0007  SC-1010 1 EA
                        └──▶ OP-A30 … OP-A90  같은 물체, 로트 유지 · state_pm_id 만 전진('함침 스테이터' …)
                              │   OP-A80·A90: proc_batch VPI-260912-07 ⊃ proc_batch_lot(스테이터 로트 30개)
                              └──◀ OP-A100  LOT-SA1000-260912-031  SA-1000
                                     └──▶ OP-B50 … ◀ OP-B120  SN-BLDC-2026-000481  완성품 【시리얼】
```

- **한 테이블인 이유**: 분할이 2단 이상(코일 → 불출 → 잔량). Lot/Sublot 두 테이블이면 "서브로트의 서브로트" 를 못 쓴다.
- **간선이 두 종류**(분할 `parent_lot_id` · 투입 `lot_genealogy`)라 추적 쿼리는 둘을 **먼저 비재귀 CTE 로 합친다**(§5.9 Q-5). SQLite 재귀 CTE 는 자기 자신을 두 번 참조하지 못한다(노하린 §5.7).
- **배치는 합침이 아니다**: 배치 처리 중에도 스테이터 로트는 각자 유지된다. `proc_batch_lot` 이 "같이 처리됨" 만 기록한다. "함침 배치 #7 불합격 → 그 30대" 는 한 번의 조인이다(R-23, V12-5).
- **진행 상태는 텍스트가 아니라 FK**: `mat_lot.state_pm_id → process_material(OUT, is_final=0)`. `processes.output` 원문은 `out_state` 에 한 번만 있다(D-9).
- 합격 기준(V-9): 밀시트 → 시리얼 정·역방향 완주 — 노하린 라운드 2 통과, v1.0 DDL 에서 재확인(§13.4).

## 4. BOM ↔ BOP 연결

### 4.1 두 축을 분리하는 이유

| | BOM | BOP |
|---|---|---|
| 답하는 질문 | 무엇으로 만드는가 | 어디서·어떤 순서로 만드는가 |
| 부모-자식 | 품목 ⊃ 품목 | 공정 순서(`seq`, `line`) |
| 바뀌는 이유 | 설계 변경(ECO) | 공법·설비 변경 |
| 테이블 | `bom_header`/`bom_line` | 기존 `processes` (쟁점 9 — 재사용 확정) |

같은 공정이 여러 라인을 소비하고(OP-B90 9라인), 한 라인이 여러 공정에 나뉠 수 있다 → N:M 연결 `process_material`.

### 4.2 연결 규칙

```
bom_line (무엇이 얼마나)  ──▶ process_material (io='IN', split_pct, issue_method) ─▶ processes ─▶ equipments.op ─▶ 설비 상태창
item     (무엇이 나오는가) ──▶ process_material (io='OUT', is_final, out_state, qty_out)
```

- 소요량은 `bom_line` 에만. `process_material` 은 "어느 공정에서 몇 %" 만(`split_pct`, R-10 합 100).
- **라인마다 BOP 연결 의도를 적는다** — `bom_line.bop_link`: `REQUIRED`(IN 필요) · `PHANTOM`(자식 팬텀, IN 금지, 트리거 자동) · `NONE`(의도적 미연결, 사유 필수). "IN 행 없음" 이 팬텀인지 누락인지 DB 가 구분한다(D-8). 뷰 `v_bom_line_bop.bop_status` = ASSIGNED / UNASSIGNED / PHANTOM / NONE.
- **OUT 행은 24공정 전부 갖는다**(D-9). `is_final=1` 7건 = 품목이 여기서 완성(로트 확정·백플러시 지점). `is_final=0` 17건 = 같은 품목의 진행 상태(`out_state` = `processes.output` 원문).
- **R-22 (신규, 노하린 제안 채택)**: 자식은 부모의 산출(`is_final`) 공정보다 늦게 투입될 수 없다 — `seq(child IN) ≤ seq(parent OUT)`, 같은 `processes.line` 안에서 트리거가 막고, 라인이 다른 쌍은 `v_chk_r22_seq` 가 "수동 확인" 으로 띄운다. 현행 데이터 위반 **0건**(PE-6000 팬텀 확정으로 유일한 위반이 사라졌다).

### 4.3 산출물에 P/N 을 부여하는 기준 (V12-3·V12-5 반영)

> **P/N 을 부여한다 — 아래 중 하나라도 해당하면**
> (a) 공정 사이에 **재고가 선다** — 별도 용기·대차로 보관·이동 *(원천 문서에 근거가 없으면 이 항목만으로는 부여하지 않는다)*
> (b) 다른 BOM·다른 공정에서 **재투입**된다
> (c) **추적 단위가 바뀐다** — 로트가 **분할되거나 새 로트로 대체**된다 (단위 kg → 매 처럼). *배치로 "같이 처리됨" 은 합침이 아니다 → `proc_batch` 로 기록(§3.3)*

### 4.4 팬텀 조립품 — HA-3000 · EX-5000 · PE-6000 (쟁점 4·5 닫힘)

| 팬텀 | 자식이 흩어지는 공정 | 조립품을 만드는 공정 | 판정 · 근거 |

| `HA-3000` | B50 / B60 / B80 — 3개 | 없음 | **팬텀** (노하린 V-12 확정) |
| `EX-5000` | B100 / B120 — 2개 | 없음 | **팬텀**. 단위 `SET` 은 등록하지 않고 `base_uom='EA'` (TC-33 의견 반영) |
| `PE-6000` | B90(9종) / B100(CN-4030) — 2개 | **없음** | **팬텀 확정.** ① OP-B90 산출 원문 "제어부 결합"(≠ 완성) ② 자식 CN-4030 이 B90 뒤 B100 투입 — 실물이면 완성 후 구성품이 못 들어간다(V12-8) ③ 단독 검사·재고 공정이 BOP 에 없다(B110 은 모터 시험). 라운드 1 의 "실물 권장" 은 **철회** |

**팬텀의 뜻(DB 규칙)**: `item.is_phantom=1` → 그 품목은 `mat_lot`·`process_material` OUT 을 가질 수 없고(트리거), 그 품목을 자식으로 갖는 라인은 `bop_link='PHANTOM'`(트리거 자동)이라 IN 을 가질 수 없다. 자식의 자식이 부모 공정으로 직접 간다. 분해도·where-used 에는 그대로 보인다.

**CN-4030 의 부모**: 원천(07시트) 대로 `PE-6000` 밑에 둔다. PE-6000 이 팬텀이면 CN-4030 이 B100 에서 투입되는 것은 구조 모순이 아니고(R-22 는 `is_final` OUT 이 있는 부모만 본다), 전개·화면 결과는 EX-5000 밑이나 완성품 직하와 **동일**하다. 원천을 고칠 근거가 없으므로 고치지 않는다.

**되돌리는 길**: PE-6000 을 실물로 운영하기로 하면 `is_phantom=0` + OUT 행(B90 is_final) + `trace_mode='LOT'` 3건 UPDATE 로 끝난다 — 단, 그때는 CN-4030 의 부모를 옮겨야 R-22 를 통과한다. **스키마 변경 없음.**

### 4.5 백플러시 지점과 방식별 계보 생성 규칙 (D-18 반영)

| 구분 | 지점 (`is_final` OUT) | 방식 | 계보(`lot_genealogy`) 행이 생기는 때 |
|---|---|---|---|
| **주 백플러시** | OP-A100 (SA-1000) · OP-B40 (RA-2000) · OP-B85 (GB-8000) · OP-B87 (PL-9000) · OP-B120 (완성품) — **5곳** | `BACKFLUSH` | 실적 신고 시 자동. `qty_consumed` = 소요량(`v_process_requirement`) × 실적 수량, 투입 로트는 그 공정 IN 의 `trace_mode∈{LOT,SERIAL}` 품목에 대해 가용 로트 FIFO. `NONE` 품목은 행을 만들지 않는다(추적 종착점) |
| 중간 산출 | OP-A10 (SC-1010P) · OP-A20 (SC-1010) | `BACKFLUSH` | 같음 |
| **수기 출고** | `SC-1011` `MW-1030` `IV-1070` `AD-2040` `SP-4040` `GB-8050` | `PICK` | 작업자가 **로트와 실투입량을 입력**할 때 1행. 소요량과 다를 수 있다(원칙 3) |

## 7. 코드 체계 · 생애주기 · 변경 관리

### 7.1 품번 체계 — 현행 존중, 규칙만 문서화

현행 BLDC 품번은 **`2문자 접두 + '-' + 4자리 일련 [+ 1문자 변형]`** 이다. 이 형식을 바꾸지 않는다.

```
S C - 1 0 1 0 P
│ │   │ │ │ │ └─ 변형 코드(선택): F/R(전후), U/L(상하), P(중간재)
│ │   │ └─┴─┴─── 일련 (같은 블록 안 순번, 10 단위로 띄움)
│ │   └───────── 계열 블록 1자리
└─┴───────────── 품목 접두 2자리 (약어)
```

| 블록 | 뜻 | 실제 품번 |
|---|---|---|
| 1xxx | 스테이터계 | SC-1010, SC-1010P, SC-1011, IN-1020U/L, MW-1030, IP-1040, LW-1050, TM-1060, IV-1070, LC-1080 |
| 2xxx | 로터계 | SH-2010, RC-2020, PM-2030, AD-2040, BW-2050 |
| 3xxx | 하우징계 | HS-3010, BP-3020F/R, BF-3040, BR-3050, WW-3060, BT-3070 |
| 4xxx | 전장·제어 부품 | PC-4010/4011, HS-4020, MO-4030, GD-4040, CP-4050, HK-4060, BB-4070, CN-4030, SP-4040 |
| 5xxx | 외장·부속 | NP-5010, OR-5020, CG-5030 |
| 7xxx | 동력전달(축) | FS-7010, FS-7021, FS-7022, FS-7023, OR-7025 |
| 8xxx | 감속부 | GB-8010~8050 |
| 9xxx | 안전장치 | PL-9010~9040 |
| x000 | **조립품**(블록의 대표) | SA-1000, RA-2000, HA-3000, PE-6000, EX-5000, FS-7020, GB-8000, PL-9000 (FS-7010 은 v1.0 부터 단품) |
| 0xxx | 포장재 (신규 블록) | PK-0010 |

| 흠 | 사례 | 판단 |
|---|---|---|
| 접두 충돌 | `HS-3010` Housing Frame vs `HS-4020` Hall Sensor | 기존 2건 개번 안 함. 접두 사전을 `mat_class` 에 붙이고 신규부터 강제 |

**신규 품번과 임시 품번**: 발번은 설계 권한. PM 승인(쟁점 1·2) 전에는 `cleansing-v1.json` `pn_pending` 의 **`TMP-` 임시 품번**(`TMP-SC1010P` `TMP-FS7023` `TMP-PK0010`)으로 적재한다. 승인되면 `approved: true` 로 바꾸고 적재기를 다시 돌리면 `UPDATE item SET pn` 한 번이다 — FK 는 `item_id` 라 BOM·공정·로트 어디에도 영향이 없다. 화면에는 승인 전까지 `TMP-` 가 보인다(의도).

### 7.2 품목 생애주기

```
[등록] DRAFT ──승인──▶ APPROVED ──양산이관──▶ ACTIVE ──단종──▶ OBSOLETE
                                                │
                                          품질보류 ▼
                                              BLOCKED ──해제──▶ ACTIVE
```

| 상태 | 뜻 | BOM에 쓸 수 있나 | 투입할 수 있나 |
|---|---|---|---|
| `DRAFT` | 등록만 됨. 도면·규격 미확정 | 아니오 (`ENG` BOM에만) | 아니오 |
| `APPROVED` | 설계 승인. 시작품 사용 가능 | 예 | 시작품만 |
| `ACTIVE` | 양산 적용 | 예 | 예 |
| `BLOCKED` | 품질 문제로 사용 보류 | 기존 라인 유지 | **아니오** (출고 차단) |
| `OBSOLETE` | 단종. 신규 BOM 금지, 기존 이력은 보존 | 아니오 | 재고 소진까지만 |

**삭제는 없다**(R-11). v1.0 부터 DB 가 `item`·`bom_header` DELETE 를 거부한다.

### 7.3 변경 관리(ECO)와 승인 권한

```
변경요청 ──▶ 영향분석 ──▶ 승인 ──▶ 적용(유효일자) ──▶ 확인
 (요청자)     (자재담당)   (권한자)    (시스템)          (검증)
   │            │            │           │
   │            │            │           └─ 새 rev의 bom_header.valid_from = eco.effective_at
   │            │            │              직전 rev의 valid_to = effective_at - 1일 (겹침 금지 R-9b)
   │            │            └─ eco.status = APPROVED, approved_by 기록 (요청자 ≠ 승인자, CHECK)
   │            └─ where-used 역전개(Q-3)로 영향 상위 품목·진행 중 작업지시 목록 산출
   └─ 사유 필수 (품질/원가/공급/설계)
```

| 작업 | 권한 | 근거 |
|---|---|---|
| 품목 등록(DRAFT) | 자재담당 | 등록만으로는 생산에 영향 없음 |
| 품목 승인(→APPROVED/ACTIVE) | 자재담당 + 설계 승인 | 도면 확정이 전제 |
| BOM 신규·리비전 올림 | **ECO 승인 필수** | IATF 16949 변경 관리 |
| BOM 라인 추가·삭제·수량 변경 | **ECO 승인 필수** | 이게 없으면 BOM을 덮어쓰게 된다 |
| 대체품 등록 | ECO 승인 필수 | |
| `BLOCKED` 설정 | 품질담당 **즉시 가능**, 사후 ECO | 불량 확산 차단이 우선 |
| 공정-자재 연결(`process_material`) 변경 | 생산기술 + 자재담당 | BOM 수량은 안 바뀌므로 ECO 불요 |
| 로트 상태 변경(HOLD/SCRAP) · 배치 판정 | 품질담당 | |
| 신규 품번 발번 · `TMP-` 해제 | PM (설계 권한) | §7.1 |

**BOM 을 덮어쓰지 않는다는 뜻**: 수량이 8 → 10 으로 바뀌면 기존 행을 UPDATE 하는 게 아니라 기존 행의 `valid_to` 를 끊고 새 행을 `valid_from` 부터 넣는다. 그래야 "작년 3월에 만든 그 모터는 볼트가 몇 개였나" 에 답할 수 있다(Q-1 `:asof`).

v1.0 에서 DB 가 보장하는 것:
- 새 rev 를 DRAFT 로 만들 때는 기간이 겹쳐도 된다. **승인(→APPROVED/ACTIVE) 순간** 직전 rev 와 겹치면 거부된다(R-9b) → 직전 rev 의 `valid_to = effective_at − 1일` 을 먼저 끊는 절차가 강제된다.
- 승인된 BOM 의 라인은 지울 수 없다(R-11). 수량 변경은 새 라인 + `valid_to`.
- `eco.requested_by ≠ approved_by` (§11.2 R5).

## 8. 추적 단위 정책

### 8.1 판정 기준

품목마다 `trace_mode` 를 **셋 중 하나**로 정한다. 정하지 않은 품목이 있으면 계보에 구멍이 난다.

| 기준 | 질문 | 해당하면 |
|---|---|---|
| A. 안전·성능 | 이 부품이 불량이면 사람이 다치거나 제품 기능이 죽는가 | LOT 이상 |
| B. 리콜 범위 | 문제가 생겼을 때 **어느 범위를 회수할지 특정**해야 하는가 | LOT 이상 |
| C. 개체 식별 | 고객·법규가 **개체 하나하나**를 요구하는가 (보증·이력카드) | SERIAL |
| D. 단가·수량 | 단가가 낮고 대량 소모되어 개별 추적 비용이 이익보다 큰가 | NONE |
| E. 유효기한 | 시간이 지나면 성능이 변하는가 (화학품) | LOT (+ 기한 관리) |

### 8.2 BLDC 적용 (확정 적재값, 쟁점 7 검토 대상)

품목 60 = SERIAL **1** + LOT **34** + NONE **25**. `PE-6000` 팬텀 확정으로 v0.9 의 LOT 35 → 34.

| trace_mode | 품목 |
|---|---|
| SERIAL (1) | `BLDC-500W-48V` — OP-B120 레이저 마킹 |
| LOT (34) | 조립품·중간품 7 `SA-1000 RA-2000 FS-7020 GB-8000 PL-9000 SC-1010 SC-1010P` · 원자재 2 `SC-1011 MW-1030` · 자석·코어 2 `PM-2030 RC-2020` · 베어링 3 · 축·기어 7 `SH-2010 FS-7010 FS-7021 FS-7022 FS-7023 GB-8020 GB-8030` · 파킹락 4 · 화학품 4 · 전장 핵심 5 `PC-4010 PC-4011 MO-4030 GD-4040 HS-4020` |

### 8.3 정책 규칙

1. 상위 LOT, 하위 NONE 은 된다(설계된 종착점).
2. 하위 SERIAL, 상위 NONE 은 안 된다 → 뷰 `v_chk_trace_serial`.
3. `BULK` 출고 품목은 NONE 이어야 한다 → 뷰 `v_chk_bulk_trace`(D-18).
4. `trace_mode` 변경은 ECO 대상이 아니다. 소급 적용하지 않는다.
