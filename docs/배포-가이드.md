# 무료 웹 배포 가이드 (Koyeb 기준, Render·기타 대안 포함)

이 앱은 Node 서버(Express + Socket.IO 실시간 + SQLite)라 GitHub Pages 같은 정적 호스팅에는 올릴 수 없고,
Node 프로세스를 상시 실행해 주는 호스팅이 필요합니다. 카드 등록 없이 되는 **Koyeb**를 기본으로, Render 등 대안을 함께 적습니다.

## 0. Koyeb 배포 절차 (약 5분, 신용카드 불필요) — 기본

1. https://www.koyeb.com 에서 GitHub 계정으로 가입 (Hobby 플랜, 무료 인스턴스 1개)
2. README의 **Deploy to Koyeb** 버튼을 누릅니다. 저장소·브랜치(main)·빌더(Dockerfile)·포트(3000)·환경변수가 미리 채워진 생성 화면이 열립니다.
   - 버튼이 안 열리면 대시보드 → **Create Service** → **GitHub** → `je31061/game_mes` 선택 → Builder **Dockerfile** → Instance **Free** →
     Ports `3000` / HTTP / path `/` → Environment variables에 아래 세 개 추가
3. 환경변수 값 바꾸기 (둘 다 `CHANGE-ME`로 들어가 있음):
   - `FW_ADMIN_PASSWORD` — 관리자 비밀번호 (공개 서버이므로 반드시 새 값)
   - `FW_JWT_SECRET` — 아무 긴 임의 문자열(32자 이상). Secret 타입으로 저장 권장
   - `FW_SELF_REGISTER` — `false` 그대로 (사전 등록된 사번만 로그인). 시연 중 누구나 로그인하게 하려면 `true`
   - `FW_SEED_PRODUCT_LINE` — `bldc` 그대로 (빈 DB에 BLDC 500W 라인 자동 적용). 파일럿 시드 10대로 시작하려면 비움
4. **Deploy** → 첫 빌드 3~5분 → `https://factory-world-<계정>.koyeb.app` 주소가 생김 (Overview의 Public URL)
5. 접속 → `admin` / `관리자` / 3에서 정한 비밀번호로 관리자 콘솔(`/admin.html`) 로그인 → 사용자 관리에서 사번 사전 등록

이후 GitHub `main`에 push할 때마다 자동으로 다시 빌드·배포됩니다(Autodeploy 기본 켜짐).

### Koyeb 무료 인스턴스에서 알아 둘 것
- **절전(scale-to-zero)**: 접속이 없으면 잠들고 첫 요청에 수십 초 걸립니다. 시연 전에 미리 한 번 열어 두세요.
- **디스크 초기화**: 재배포·재시작 때 컨테이너가 새로 뜨므로 DB는 시드 데이터로 돌아가고 업로드·평면도도 사라집니다. 데모·검증용으로 쓰고, 맵 구성은 관리자 콘솔 [⬇ 배치 JSON 내보내기]로 받아 두세요.
- **리전**: 무료 인스턴스는 Washington(`was`) 또는 Frankfurt(`fra`)만 가능합니다. 한국에서 응답은 0.2~0.3초 수준이라 시연에는 무리 없습니다.
- **로그**: 서비스 → Logs에서 `[Factory World] http://localhost:3000` 줄이 보이면 정상 기동입니다. 빌드 실패 시 Build logs 확인.
- **WebSocket**: 기본 지원. 별도 설정 없음.

## 1. Render 배포 절차 (대안, 신용카드 불필요)

1. https://render.com 에서 GitHub 계정으로 가입
2. 저장소 README의 **Deploy to Render** 버튼을 누르거나, 대시보드에서 **New → Blueprint** → `je31061/game_mes` 선택
   (저장소의 `render.yaml`이 서비스 설정을 그대로 만들어 줍니다)
3. 환경변수 입력 화면에서 **FW_ADMIN_PASSWORD**에 관리자 비밀번호를 정해 넣기 (공개 서버이므로 반드시 새 값)
4. Apply → 3~5분 뒤 `https://factory-world-xxxx.onrender.com` 주소가 생김
5. 접속 → 관리자(`admin` / `관리자` / 3에서 정한 비밀번호)로 로그인 → 관리자 콘솔에서 사용자 사전 등록

이후 GitHub `main`에 push할 때마다 자동으로 다시 배포됩니다.

- **현재 체험 서버**: https://factory-world.onrender.com (이 저장소 `main`, Blueprint 자동 동기화 — `render.yaml`을 바꾸면 서비스 설정도 따라 바뀜).
  `FW_SEED_PRODUCT_LINE=bldc`라 재배포 직후에도 BLDC 500W 라인(설비 24·공정 24·존 2)으로 시작합니다.
- **반영 확인(로그인 없이)**: `/js/app.js`에 `eq-proc-section` 문자열이 있고, `/assets/equipment/winder.png`·`/assets/parts/thumb/SA-1000.png`가 200,
  `/api/bop/exploded`가 비로그인 401이면 스프린트 2 코드가 올라간 것입니다. 무료 플랜은 빌드·기동에 수 분 걸립니다.
- 문서만 고친 커밋은 커밋 메시지에 `[skip render]`를 넣으면 자동 재배포를 건너뜁니다(재배포마다 DB가 초기화되므로 시연 중에는 유용).

## 2. 무료 플랜에서 알아 둘 것

| 항목 | 내용 | 대응 |
|---|---|---|
| 절전 | 15분 동안 접속이 없으면 잠들고, 다음 접속에 30~60초 걸림 | 시연 전에 미리 한 번 열어 두기 |

| 자동 등록 | `FW_SELF_REGISTER=false`라 사전 등록된 사번만 로그인 가능 | 관리자 콘솔 → 사용자 관리에서 등록, 또는 운영 정책에서 켜기 |

| 게이트웨이 | MQTT 브로커가 인터넷에서 접근 가능해야 LIVE, 아니면 SIM | 사내 장비 연동은 사내 서버에서 |

## 3. 데이터를 남기려면

- **Render 유료 디스크**: 서비스에 Disk(최소 1GB, 월 $0.25 수준)를 붙이고 마운트 경로를 `/var/data`로, 환경변수 `FW_DATA_DIR=/var/data`로 지정. 무료 플랜에서는 디스크를 붙일 수 없어 Starter 플랜(월 $7)이 필요.
- **Fly.io**: 볼륨(3GB까지 무료 할당이 있었으나 계정 정책이 자주 바뀜)에 `FW_DATA_DIR`을 마운트. `fly launch` → `fly volumes create fwdata` → `[mounts]`에 `/data`.
- **사내 서버**: 가장 확실한 방법. `docs/운영전환-가이드.md`의 절차로 사내 PC/서버에 상시 가동하고 HTTPS를 붙입니다.

## 4. 다른 무료 호스팅 — 저장소의 `Dockerfile`로 모두 배포 가능

| 서비스 | 카드 | 절전 | 데이터 유지 | 배포 방법 |
|---|---|---|---|---|
| Render (free) | 불필요 | 15분 | ✗ | 이 문서 1절 (render.yaml) |
| **Koyeb (free)** | 불필요 | 미접속 시 | ✗ | 대시보드 → Create Service → GitHub `je31061/game_mes` → Builder **Dockerfile** → 환경변수 `FW_ADMIN_PASSWORD`, `FW_JWT_SECRET`, `FW_SELF_REGISTER=false`, `FW_SEED_PRODUCT_LINE=bldc` → 포트 3000 |
| **Hugging Face Spaces** | 불필요 | 48시간 | ✗ (유료 저장소) | New Space → SDK **Docker** → 저장소 내용 push (Space 설정 `app_port: 3000`) → Settings의 Variables/Secrets에 위 환경변수 |
| **Oracle Cloud Always Free VM** | 필요(과금 없음) | 없음 | ✅ | Ubuntu VM 생성 → `docker run -d -p 80:3000 -v fwdata:/data -e FW_ADMIN_PASSWORD=... --restart unless-stopped ghcr...`(또는 저장소 clone 후 `docker build`) → 보안 목록에 80/443 개방 → HTTPS는 Caddy 리버스 프록시 |
| Fly.io | 필요 | 선택 | ✅ 볼륨 | `fly launch`(Dockerfile 자동 감지) → `fly volumes create fwdata` → `fly.toml` `[mounts] source="fwdata" destination="/data"` |
| Railway | 체험 후 유료 | 없음 | ✅ 볼륨 | GitHub 연결, 볼륨을 `/data`에 마운트 |
| Vercel / Netlify / GitHub Pages / Cloudflare Pages | — | — | — | ❌ 서버리스·정적이라 Socket.IO 상시 연결 불가 |

컨테이너는 `FW_DATA_DIR=/data`로 동작하므로, 볼륨을 `/data`에 붙이면 DB·업로드·백업이 유지됩니다. 로컬 확인:

```bash
docker build -t factory-world . && docker run -p 3000:3000 -e FW_ADMIN_PASSWORD=Pilot-2026 -v fwdata:/data factory-world
```

## 5. 배포용 환경변수 요약

| 변수 | 용도 |
|---|---|
| `PORT` | 호스팅이 자동 지정 (서버가 읽음) |
| `FW_JWT_SECRET` | 로그인 세션 서명 키 고정 (없으면 디스크 파일 사용) |
| `FW_ADMIN_PASSWORD` | 빈 DB로 시작할 때 admin 초기 비밀번호 (없으면 admin1234) |
| `FW_SELF_REGISTER` | `false`면 사전 등록된 사번만 로그인 (콘솔 정책이 설정되면 그 값 우선) |
| `FW_SEED_PRODUCT_LINE` | `bldc`면 빈 DB로 기동할 때 BLDC 500W 제품 라인(공정 24·설비 24·존 2, 시드 설비 10대는 숨김)을 1회 자동 적용 — 재배포로 DB가 초기화돼도 데모가 제품 라인으로 뜸. `render.yaml`에 포함. Koyeb는 Deploy 버튼 URL에 포함, 수동 생성 시 직접 추가 |
| `FW_DATA_DIR`, `FW_BACKUP_DIR`, `FW_BACKUP_HOUR`, `FW_TLS_*` | 운영 전환 가이드 참조 |
