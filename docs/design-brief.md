# Factory World 소개 페이지 브리프

> 이 문서는 "Factory World가 무엇이고, 왜, 어떻게 만들었는가"를 웹으로 설명하는 페이지를 만들 때의 원천 자료입니다.
> 원본 근거: `게임형_MES_기안_및_기본설계서.docx`(2026-08-13, ICT 총괄), `README.md`, `docs/구축경과보고.html`.

## 1. 대상 독자와 목적

- 독자: 사내 경영진·생산/보전 현업 리더·ICT 구성원. 개발자가 아닌 사람이 먼저 이해해야 한다.
- 목적: (1) 왜 MES를 게임처럼 만들었는지 납득시키고, (2) 어떤 방식으로 작업했는지 투명하게 보여주고, (3) 다음 단계(파일럿) 협조를 이끌어낸다.
- 톤: 차분하고 사실적. "게임"이라는 단어에 대한 사내 거부감을 고려해 **"디지털 트윈형 협업 MES"**를 병기한다(기안서 리스크 항목).

## 2. 취지 (왜 만들었나)

### 문제
- 기존 MES는 표·그리드 화면이라 현장 몰입도와 사용률이 낮다. 입력 회피, 형식적 사용이 만연하다.
- 설비 이슈 대응이 전화·메신저에 흩어져 조직의 자산으로 남지 않는다.
- 관리자와 현장이 같은 그림을 보지 못한다.

### 해법: 공장을 게임 맵으로
- **공장 = 맵**: 실제 레이아웃을 아이소메트릭(쿼터뷰) 타일맵으로 재현. 설비는 건물, 공정 구역은 존(Zone). 벤치마킹: 심시티.
- **작업자 = 캐릭터**: 로그인하면 자기 캐릭터로 "출근". 색상·닉네임·직무 뱃지.
- **설비 상태 = HUD**: 설비를 클릭하면 게임식 상태창. 가동/대기/정지/알람, 지속 시간, 금일 가동률(HP바), 이력, 첨부.
- **협업 = 근접 대화**: 두 명 이상이 같은 설비 근처에 모이면 그 설비 이름의 대화방이 자동으로 열린다. 벤치마킹: 게더타운. 대화·파일·조치가 그 설비의 이력으로 자동 기록된다.

### 대표 시나리오 (설비 이상 대응)
1. 3번 프레스에 알람 → 맵 위 설비가 붉게 점멸, 담당자에게 알림
2. 현장 작업자 A와 사무실의 보전 담당 B가 각자 캐릭터를 3번 프레스 앞으로 이동
3. 근접하는 순간 '프레스 3호기' 대화방 자동 활성화
4. A가 현장 사진 업로드, B가 점검 매뉴얼 PDF 전달, 조치 방법 합의
5. 조치 완료. 대화·파일·소요 시간이 설비 이력으로 저장되어 이후 같은 이슈에서 검색 가능

### 기대효과
- 이슈 대응 시간 단축 (파일럿 목표: 평균 30%)
- 설비별 조치 노하우의 자산화
- 관리자·경영진의 한 화면 가시성
- 낮은 진입 장벽으로 현장 자발적 사용 → 이후 MES 코어 기능 확산의 기반

## 3. 작업 방식 (어떻게 만들었나)

### 원칙
1. **완성형을 처음부터 만들지 않는다.** Phase 1은 "맵 + 협업"에만 집중. 설비 연동(P2), 생산관리·게임성(P3)은 모듈로 추가.
2. **맵과 설비는 코드가 아니라 데이터.** 관리자 콘솔의 맵 에디터에서 존 영역·설비 배치·라인 연결을 드래그로 바꾼다. 코드 수정 없음.
3. **수동 상태 변경과 자동 수집은 같은 이벤트 규격.** 그래서 MQTT 실연동을 붙일 때 게임 화면은 한 줄도 고치지 않았다.
4. **근접 판정은 서버가 한다.** 기록의 신뢰성을 위해서다.
5. **기록은 append-only.** 대화·파일·상태 변경은 수정·삭제 불가. 감사 추적 가능.
6. **재미가 업무를 방해하지 않게.** 1단계는 시각화와 협업, 게이미피케이션은 3단계로 유보.

### 단계별 로드맵과 실제 진행
| 단계 | 기획 범위 | 실제 결과 |
|---|---|---|
| Phase 1 (MVP) | 로그인·캐릭터·맵·상태창·다중접속·근접대화·파일·기록·관리자 콘솔 | 전부 구현. 2인 동시 접속으로 대표 시나리오 검증 |
| Phase 2 | 설비 연동 게이트웨이 (OPC-UA/Modbus/MQTT) | MQTT는 실연동(LIVE), OPC-UA/Modbus는 시뮬레이션(SIM) |
| Phase 3 | 작업지시(퀘스트)·실적·포인트/레벨/리더보드·라인 시뮬레이션 | 퀘스트, 실적/불량 등록, 포인트·뱃지·개인/팀 리더보드, 심시티식 라인 부하(정체 알림) 구현 |

### 구축 진행 순서 (경과보고 기준)
1. 게임형 협업 공간 (Phase 1 MVP)
2. 관리자 콘솔: KPI·대화 로그 검색·마스터 관리·알람 대응 리포트
3. 맵 에디터 + 절차 생성 도트 캐릭터 (외부 에셋 없이)
4. 설비 게이트웨이: MQTT 실연동
5. 인증 강화: scrypt 비밀번호, JWT, 역할 3종(작업자/보전/관리자)
6. Phase 3 게임성: 퀘스트·포인트·리더보드
7. 공정 라인 부하: 라인 연결, 재공 부하 모델, 정체 알림

### MVP 기술 선택 (단순화와 전환 경로)
| 기획서 목표 스택 | MVP 선택 | 이유 |
|---|---|---|
| Next.js | 순수 HTML/JS (빌드 없음) | 빠른 검증 |
| NestJS | Express 단일 서버 | 외부 인프라 0개로 실행 |
| PostgreSQL | SQLite (Node 내장) | 스키마는 기획서 데이터 모델 유지 |
| Redis | 메모리 Map | 다중 서버 확장 시 도입 |
| MinIO | 로컬 파일 저장 | 사전서명 URL로 전환 가능 |
| Phaser 3 / Socket.IO | 동일 | 그대로 |

핵심 메시지: `npm install && npm start` 한 줄로 사내 PC 어디서나 뜬다. 외부 인프라가 없다.

### 검증 방식
- 브라우저 2개 탭(작업자 / 보전·관리자)으로 시나리오 검증: 근접 대화 활성화, 실시간 동기화, 권한 차단, 퀘스트 보상, 라인 정체 알림
- MQTT는 로컬 브로커를 띄워 실제 발행 → 맵 반영·이력 기록 확인
- 인증은 누락(400)/오류(401)/권한 우회(403) 경계 케이스 포함

### 기대효과의 측정 근거
- 관리자 콘솔의 알람 대응 리포트: 알람 발생→해제 에피소드별 대응 시간, 해제자, 협업 지표(대화 수·참여자·파일)
- 이것이 "대응 시간 30% 단축" 주장을 숫자로 뒷받침하는 장치

### 실제 공장 도면을 맵으로 옮기는 방법 (반드시 페이지에 포함)
맵은 코드가 아니라 데이터라는 원칙의 실제 사용법이다. 관리자 콘솔의 맵 에디터에서 세 가지를 제공한다.

1. **평면도 배경**: 건축 배치도·설비 설계도를 이미지(PNG/JPG/WEBP/SVG)로 올리면 에디터 격자 아래에 깔린다.
   투명도와 도면이 덮을 타일 범위를 조정하고, 그 위에서 존 영역을 드래그하고 설비를 끌어다 놓는다.
   "게임 맵에도 표시"를 켜면 현장 화면의 아이소메트릭 바닥에 같은 도면이 투영되어, 작업자가 실제 배치와 같은 그림 위를 걷는다.
2. **배치 데이터 JSON**: 존·설비·라인을 JSON으로 내보내고 가져온다. 존은 이름, 설비는 코드 기준으로 추가·갱신되며 삭제는 하지 않는다(이력 보호).
3. **Claude / Gemini 연동**: 도면 이미지를 AI에게 주고 정해진 프롬프트(24×16 격자, 좌표 추정 규칙, JSON 스키마)를 붙이면
   AI가 배치 JSON을 만들어 준다. 그 파일을 가져오기 하면 도면 위에 존과 설비가 겹쳐 보이고, 어긋난 것만 드래그로 바로잡는다.
   PDF·DWG 도면은 이미지로 내보낸 뒤 사용한다. 스키마와 프롬프트 전문은 `docs/도면-AI-연동.md`.

메시지: "도면이 있으면 반나절이면 우리 공장이 맵이 된다. 손으로 옮기지 않고 AI가 초안을 잡고 사람이 검수한다."

### 화면 테마
- 기본은 게임 감성의 다크 테마. 상단 🌓 버튼으로 **흰 바탕(라이트) 테마**로 전환할 수 있다.
  밝은 현장 조명, 경영진 보고 화면, 인쇄에 맞춘 것으로 맵·상태창·관리자 콘솔이 함께 바뀐다. 설정은 브라우저에 저장된다.
- ⚡ 저사양 모드(애니메이션 끄고 30fps)와 터치 방향 패드로 구형 태블릿에 대응한다.

## 4. 현재 상태와 남은 과제

- 기능 요구사항 13개 전부 동작. FR-11은 MQTT 실연동, OPC-UA/Modbus는 드라이버 준비(라이브러리 설치 시 연결)
- 운영 기반 완료: 매일 자동 백업(관리자 대시보드에서 확인·즉시 실행), 서버 자동 재기동·클라이언트 자동 재접속,
  HTTPS 옵션, 동시 50명 부하 테스트 통과(이동 동기화 p95 20ms, 채팅 12ms; 기준 200ms/1초)
- 현장 사용성: 상태창 목표 대비 진행률 게이지, 담당자 호출, 출근 브리핑, 저사양 모드, 태블릿 대응, 라이트 테마
- 남은 과제: 사내 계정 연동(SSO/AD — 현재 사내 인증 서버 없음), OPC-UA/Modbus 실 장비 검증, 파일럿 라인 1개 선정 후 실사용 피드백, 사용자 사전 등록 정책

## 5. 페이지에 넣지 말 것

- 관리자 계정·비밀번호, JWT 시크릿, 내부 저장소 URL의 인증 정보
- 개인 사번·실명 (시드 데이터의 담당자명 "김보전" 등 가상 이름은 무방)
