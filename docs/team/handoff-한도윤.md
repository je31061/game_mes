### 한 일
1. **`assets/blender/build_equipment.py`** (Blender 5.2.1 bpy, 배치 실행)
   - 설비 7종 절차 모델: press(C-프레임+상하 램+플라이휠+라이트커튼), welder(청색 전원 캐비닛+피더+가스통+토치·호스+작업대+황색 차광막),
     robot(6축 주황 팔+베이스+제어반+황색 펜스), assembly(녹색 벨트 컨베이어+양끝 롤러+갠트리 헤드+황색 가드+페데스탈),
     inspector(백색 비전 게이트+카메라·링라이트+모니터), packer(투입 터널+개구+골판지 상자+필름 롤), cnc(밀폐 외장+검은 창+펜던트+툴 매거진 타워+칩 컨베이어).
     전 유형에 회색 프레임·황색 가드·적색 비상정지·경광등 몸통 포함.
   - 카메라 직교 (60°, 0, 45°), `ortho_scale = 3·타일·√2`(프레임 폭 = 타일 3칸 → 마름모 64px), `shift_y = +0.28125`(원점 → (96,150)).
   - 조명: 키 선(그림자 O, 카메라 왼쪽 앞) + 필 선 2개(그림자 X) + 월드 주변광. 뷰 변환 Standard(채도 유지).
   - 엔진: EEVEE(5.2 식별자 `BLENDER_EEVEE`, enum_items로 자동 선택). `--engine cycles`면 Cycles 애드온을 켜서 CPU 64샘플.
   - 유형별 2패스: `_body.png`(본체, 투명) + `_shadow.png`(설비를 `visible_camera=False`·holdout으로 숨기고 바닥만 → 그림자 휘도).
   - `meta.json`: 램프·원점·타일 꼭짓점의 정확한 픽셀 투영(`world_to_camera_view`), 유형별 최고점.

   - `_calib.png`(타일 1칸 평면) 측정으로 마름모 64×32·중심 (96,150) 검증. 어긋나면 정수 오프셋으로 전 스프라이트 정렬(현재 오프셋 0).

- `lamp`는 경광등 몸통(검은 원기둥) 중심의 정확한 투영 좌표. 게임이 그리는 반지름 5 원이 몸통 위에 얹힌다(3배 확대 시트로 7종 확인).
- `labelY = max(8, min(top-10, lamp.y-16))` — 라벨 12px 텍스트가 설비 최고점·램프 광원(r9)과 겹치지 않는 값.
- `anchor`(96,150), `tile`(64×32)는 규격 그대로.

### 최민준에게 (라운드 3)
1. **로더 확인**: `public/assets/equipment/` 에 7종 PNG + manifest 배치 완료. 게임 맵에서 11대 전부 이미지 스프라이트로 바뀌는지, 라이트 테마·저사양 모드에서 확인 부탁.
2. **램프 좌표**: 표의 lamp 값이 경광등 몸통 위에 오는지 실제 화면에서 한 번 봐 달라. 어긋나면 어느 유형이 몇 px인지 알려주면 모델을 옮긴다(좌표를 손으로 고치지 말고 스크립트에서 재생성).
3. **라벨**: labelY는 설비 상단 10px 위. 라벨이 이웃 타일 설비와 겹치면 게임 쪽에서 labelY를 더 올리는 것보다 매니페스트 값을 조정하는 편이 낫다 — 원하는 오프셋을 알려 달라.
4. **.gitignore**: `assets/blender/out/`(중간 렌더·meta) 추가 요청. `.blend`는 만들지 않는다(스크립트 재생성).
5. **인터페이스 §2 카메라 각도**: 63.435° → **60°** 로 고쳤다(§2는 내 소유). 이유: 카메라 X회전 rx의 바닥 마름모 종횡비는 1/cos(rx). 63.435°는 2.236:1(마름모 높이 28.6px), 60°가 정확히 2:1(64×32). 캘리브레이션 실측으로 확인. 다른 문서(README 등)에 63.435°가 인용돼 있으면 함께 고쳐 달라.
6. **클릭 영역**: 그림자 알파를 28 이상으로 둬서 그림자도 클릭된다(규격대로). 현장에서 그림자 클릭이 거슬리면 postprocess의 `SHADOW_A_MIN`을 20으로 내리면 그림자는 통과된다 — 정책 결정 부탁.
