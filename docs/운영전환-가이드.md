# Factory World 운영 전환 가이드

파일럿(단일 PC, SQLite)에서 운영 환경으로 옮길 때 필요한 절차를 정리한 문서입니다.
기준: 기획서 NFR-01(성능)·NFR-03(보안)·NFR-04(가용성), README의 기술 스택 전환표.

## 1. 환경 변수

서버는 코드 수정 없이 아래 환경 변수로 운영 설정을 바꿉니다.

| 변수 | 기본값 | 용도 |
|---|---|---|
| `PORT` | 3000 | 서비스 포트 |
| `FW_DATA_DIR` | `<프로젝트>/data` | DB·업로드·JWT 시크릿 폴더. 부하 테스트·스테이징은 다른 폴더로 격리 |
| `FW_BACKUP_DIR` | OneDrive의 `FactoryWorld-백업` → 없으면 `<프로젝트>/backups` | 백업 대상 폴더 |
| `FW_BACKUP_HOUR` | 3 | 일 단위 자동 백업 시각(0~23시) |
| `FW_TLS_CERT`, `FW_TLS_KEY` | (없음) | PEM 인증서·키. 둘 다 있으면 HTTPS/WSS로 기동 |

PowerShell 예:

```powershell
$env:PORT = 8443
$env:FW_DATA_DIR = 'D:\fw-data'
$env:FW_BACKUP_DIR = '\\nas\backup\factory-world'
$env:FW_TLS_CERT = 'D:\fw-cert\fullchain.pem'
$env:FW_TLS_KEY = 'D:\fw-cert\privkey.pem'
npm start
```

## 2. 가용성 (NFR-04)

### 자동 백업
- 서버가 켜져 있으면 매일 `FW_BACKUP_HOUR`시에 자동 백업합니다. DB는 `VACUUM INTO` 스냅샷(가동 중 안전), 업로드 파일과 JWT 시크릿을 함께 복사하며 최근 14개만 보존합니다.
- 관리자 콘솔 → 대시보드 → "데이터 백업"에서 마지막 백업 시각·결과를 보고 [지금 백업]으로 즉시 실행할 수 있습니다.
- 서버와 무관하게 돌리려면 `backup.cmd`를 Windows 작업 스케줄러에 등록합니다.

### 복구
1. 서버 정지
2. 백업 폴더(`fw-backup-YYYYMMDD-HHMMSS`)의 `factory.db`, `uploads/`, `jwt.secret`을 `FW_DATA_DIR`(기본 `data/`)에 복사
3. 서버 시작. `jwt.secret`을 함께 복원해야 기존 로그인 세션이 유지됩니다.

### 자동 재기동·재접속
- `start.cmd`는 서버가 오류로 종료되면 3초 후 자동 재기동합니다(Ctrl+C 정상 종료는 제외).
- 클라이언트는 연결이 끊기면 자동 재접속하고 맵·접속자·내 위치를 다시 맞춥니다.
- 게이트웨이는 관리자가 켜 둔 상태를 기억해 서버 재시작 시 자동 재개합니다.
- 서비스로 상시 가동하려면: 작업 스케줄러에 "로그온 시" 트리거로 `start.cmd`를 등록하거나, NSSM으로 `node server\index.js`를 Windows 서비스로 등록합니다.

## 3. 보안 (NFR-03)

- **HTTPS/WSS**: 사내 인증서를 발급받아 `FW_TLS_CERT/KEY`로 지정하거나, IIS·nginx 리버스 프록시가 TLS를 종단하고 `http://localhost:3000`으로 전달하도록 구성합니다. 프록시 사용 시 WebSocket 업그레이드(`Upgrade`/`Connection` 헤더) 전달을 켜야 합니다.
- **관리자 초기 비밀번호**: 첫 로그인 후 반드시 변경합니다(게임 상단 🔑).
- **사용자 등록 정책**: 관리자 콘솔 → 사용자 관리 → 운영 정책에서 "신규 사번 자동 등록 허용"을 끄면 사전 등록된 사번만 로그인할 수 있습니다. 운영 전환 시 사용자를 사전 등록(사번·이름·역할·팀)한 뒤 끄는 것을 권장합니다. 사내 계정(SSO/AD)은 현재 없음.
- **보존 기간 정책(FR-08, 기안서 리스크 "개인정보/노무")**: 같은 화면에서 대화·파일 보존 일수를 정하면 매일 자동 백업이 성공한 직후 기간이 지난 대화·파일이 정리됩니다(백업본에는 남음). 상태 이력·실적·포인트는 KPI 원천이므로 보존됩니다. 도입 전 업무 채널 한정 기록임을 고지·동의받고 보존 일수를 노무 협의로 정하세요.
- **1일 계획 가동 시간 정책**: 같은 운영 정책 카드의 "1일 계획 가동 시간(분, 1~1440)"은 📈 실적 분석 탭 가동률의 분모(계획 시간)입니다. 비우면 24시간/일로 계산되며, 교대 시작 시각이 없으므로 하루 총량만 적용됩니다. 2교대 16시간 라인이면 960을 넣으세요. 대시보드·상태창의 "가동률(로그 구간)"은 정의가 달라 숫자가 다르게 보이는 것이 정상입니다 — 정의는 [docs/분석-정의.md](분석-정의.md).
- `data/`(DB·시크릿·업로드)와 백업 폴더는 접근 권한을 서버 계정과 관리자로 제한합니다.

## 3-1. 📈 실적 분석 (스프린트 1)

관리자 콘솔 📈 실적 분석 탭에서 설비별 OEE(가동률·성능·품질), 일별 생산실적, 게이트웨이 연결 품질을 기간·설비 필터로 봅니다.
실적·목표는 작업지시 완료 시 수동 입력 값이고 게이트웨이는 수량을 수집하지 않으므로, 목표가 없는 설비는 성능·OEE가 "—"로 표시됩니다(추정하지 않음).
첫 상태 로그 이전 시간은 "상태 미확인"으로 따로 보고합니다. 모든 지표의 분자·분모·null 조건은 [docs/분석-정의.md](분석-정의.md)가 원천입니다.

## 4. 성능 검증 (NFR-01)

동시 50명 기준, 위치 동기화 200ms 이내, 채팅 1초 이내. 운영 DB를 건드리지 않도록 별도 데이터 폴더로 테스트 서버를 띄운 뒤 부하 스크립트를 실행합니다.

```powershell
# 터미널 1 — 테스트 서버 (별도 DB, 포트 3001)
$env:FW_DATA_DIR = 'data-loadtest'; $env:PORT = 3001; npm start

# 터미널 2 — 50명 60초
node scripts/load-test.js --users 50 --duration 60 --url http://localhost:3001
```

결과에 이동 동기화 p50/p95/max, 손실 건수, 채팅 p50/p95가 출력되고 기준 충족 여부를 판정합니다. 테스트 사용자(사번 `lt-1`~)는 테스트 DB에만 생성됩니다. 끝나면 `data-loadtest/` 폴더를 삭제하면 됩니다.

최근 기록: 2026-09-08(스프린트 1 통합 후, 50명 30초) — 접속 50/50 · 이동 p50 6.0ms / p95 21.1ms / max 27.0ms(손실 1건) · 채팅 p50 1.7ms / p95 10.1ms → 통과.

## 5. 저장소 전환 경로 (기획서 스택으로 확장할 때)

MVP는 외부 인프라 없이 동작하도록 단순화했습니다. 전 공장 확대나 다중 서버가 필요해지면 아래 순서로 전환합니다.

| 영역 | 현재 | 전환 대상 | 손댈 곳 |
|---|---|---|---|
| DB | SQLite (`server/db.js`, node:sqlite) | PostgreSQL | `db.js`의 스키마·`queries` 객체만 교체. 스키마는 기획서 7장 데이터 모델을 그대로 따르므로 테이블 정의는 대응됨. `datetime('now','localtime')` → `now()`, `INSERT OR IGNORE` → `ON CONFLICT DO NOTHING` |
| 파일 | 로컬 `data/uploads` (`/api/upload`, `/api/files/:id`) | MinIO/S3 | 업로드 핸들러를 사전서명 URL 발급으로, 다운로드를 리다이렉트로 교체. `files` 테이블은 그대로 |
| 세션·Presence | 메모리 Map(`players`), 단일 프로세스 | Redis + Socket.IO Redis 어댑터 | `players`를 Redis 해시로, `io.adapter(createAdapter(...))` 추가. 근접 판정은 그대로 서버에서 |
| 설비 연동 | mqtt 내장, opcua/modbus는 드라이버 준비 | 실 장비 | `npm install node-opcua modbus-serial` 후 맵 에디터에서 주소·태그·상태 매핑 입력 (README "OPC-UA / Modbus 활성화") |
| 실행 | `npm start` / `start.cmd` | Docker Compose → Kubernetes | `Dockerfile`(node:24-alpine, `npm ci`, `node server/index.js`)과 `FW_DATA_DIR` 볼륨 마운트 |

전환 원칙: 이벤트 규격(`equipment:status`, `chat:message` 등)과 REST 경로는 유지하므로 클라이언트(`public/`)는 수정하지 않습니다.
