# 공장 도면을 맵으로 옮기기 — 평면도 배경 · 배치 JSON · Claude/Gemini 연동

실제 공장의 건축 배치도·설비 배치 설계도를 Factory World 맵에 반영하는 세 가지 방법입니다.
셋 다 관리자 콘솔 → 맵 에디터에서 이루어지며, 코드 수정 없이 데이터만으로 맵이 바뀝니다(NFR-02).

## 1. 평면도 이미지를 배경으로 깔기

1. 도면을 **PNG/JPG/WEBP/SVG** 이미지로 준비합니다. PDF·DWG는 뷰어에서 이미지로 내보냅니다
   (AutoCAD: 플롯 → PNG, PDF 뷰어: 페이지를 이미지로 저장). 상단에서 본 평면도여야 합니다.
2. 맵 에디터 → 평면도 [파일 선택] → 업로드. 에디터 격자 아래에 도면이 깔립니다.
3. **투명도**(0.1~1)와 **범위**(도면이 덮을 타일 사각형: X, Y, 폭, 높이)를 조정합니다. 맵은 24×16 타일입니다.
   도면 비율이 맵과 다르면 범위의 폭·높이를 도면 비율에 맞춰 줄이면 왜곡 없이 들어갑니다.
4. **게임 맵에도 표시**를 켜면 현장 화면의 아이소메트릭 바닥에도 같은 도면이 투영되어 깔립니다.
   끄면 에디터에서만 보이는 작업용 밑그림이 됩니다.
5. 도면 위에서 존 영역을 드래그하고 설비를 끌어다 놓으면 배치가 끝납니다.

평면도 파일은 `data/floorplan/`에 저장되고 백업에 포함됩니다.

## 2. 배치 데이터(JSON) 내보내기 · 가져오기

맵 에디터 → 배치 데이터 → [⬇ 내보내기]로 현재 존·설비·라인을 JSON으로 받고,
[⬆ 가져오기]로 JSON을 올리면 **존은 이름, 설비는 코드 기준으로 추가·갱신**됩니다. 라인은 코드 쌍으로 추가됩니다.
삭제는 하지 않으므로(이력이 걸려 있는 설비 보호) 빼야 할 설비는 콘솔에서 직접 정리합니다.

```json
{
  "version": 1,
  "map": { "w": 24, "h": 16 },
  "zones": [
    { "name": "프레스 존", "color": "#2d4a6b", "rect": { "x": 1, "y": 1, "w": 10, "h": 6 } }
  ],
  "equipments": [
    { "code": "PRS-01", "name": "프레스 1호기", "type": "press", "zone": "프레스 존", "x": 3, "y": 2, "manager": "김보전" }
  ],
  "links": [
    { "from": "PRS-01", "to": "PRS-02" }
  ]
}
```

| 필드 | 규칙 |
|---|---|
| `zones[].name` | 필수. 같은 이름이 있으면 갱신 |
| `zones[].rect` | 타일 좌표. x 0~23, y 0~15, w 1~24, h 1~16 |
| `zones[].color` | `#rrggbb`. 생략 시 기존 색 또는 기본색 |
| `equipments[].code` | 필수. 같은 코드가 있으면 갱신(연동 설정은 유지) |
| `equipments[].type` | 선택. 설비 유형 `press / welder / robot / assembly / inspector / packer / cnc / generic`. 생략하면 기존 값 유지, 신규는 코드 접두(PRS-, WLD-, ASM-, INS-, PKG-, CNC-)로 추정. 게임 맵의 실사형 스프라이트와 실적 분석 분류에 사용 |
| `equipments[].zone` | 존 이름. 없거나 틀리면 좌표가 속한 존으로 배치 |
| `equipments[].x, y` | 타일 좌표 (정수) |
| `links[].from, to` | 설비 코드. 둘 다 있어야 추가 |

가져오기 뒤 결과 줄에 추가/수정 건수와 경고가 표시됩니다. 예시 파일: `docs/layout-sample.json`.

## 3. Claude / Gemini로 도면을 JSON으로 바꾸기

도면을 보고 존과 설비 좌표를 손으로 옮기는 대신, AI에게 도면 이미지와 아래 프롬프트를 주면 위 스키마의 JSON을 만들어 줍니다.
결과를 파일로 저장해 [⬆ 가져오기]하면 됩니다. Claude(claude.ai)와 Gemini 모두 이미지 첨부와 JSON 출력을 지원합니다.

### 프롬프트 (복사해서 사용)

```
아래 공장 배치도 이미지를 보고, 게임형 MES "Factory World"의 맵 배치 JSON을 만들어 줘.

규칙:
- 맵은 가로 24칸 × 세로 16칸 격자다. 이미지의 왼쪽 위가 (0,0), 오른쪽 아래가 (23,15)다.
- 이미지의 가로를 24등분, 세로를 16등분해서 각 요소의 격자 좌표를 정수로 추정해라.
- zones: 공정 구역(예: 프레스, 용접, 조립, 검사/출하)마다 하나. rect는 구역이 차지하는 격자 사각형 {x,y,w,h}.
  color는 구역별로 구분되는 어두운 톤의 #rrggbb.
- equipments: 설비마다 하나. code는 영문 약어-번호(예: PRS-01), name은 도면에 적힌 이름, zone은 속한 존 이름,
  x,y는 설비 중심의 격자 좌표. 같은 칸에 두 설비를 두지 마라. manager는 비워 둬라("").
  type은 설비 종류로 press(프레스)/welder(용접기)/robot(로봇)/assembly(조립 라인·컨베이어)/inspector(검사기)/packer(포장기)/cnc(CNC 가공기)
  중 하나, 판단이 안 되면 "generic".
- links: 공정 흐름(화살표, 컨베이어, 공정 순서)이 보이면 상류→하류 순서로 {from, to} (설비 code).
- 도면에서 읽을 수 없는 값은 추측하지 말고 생략해라.
- 설명 없이 JSON만 출력해라. 스키마:

{"version":1,"map":{"w":24,"h":16},
 "zones":[{"name":"","color":"#2d4a6b","rect":{"x":0,"y":0,"w":1,"h":1}}],
 "equipments":[{"code":"","name":"","type":"generic","zone":"","x":0,"y":0,"manager":""}],
 "links":[{"from":"","to":""}]}
```

### 요령
- 도면 이미지를 먼저 평면도로 업로드해 두고, AI가 만든 JSON을 가져오면 도면 위에 결과가 겹쳐 보이므로 어긋난 좌표를 드래그로 바로잡기 쉽습니다.
- 도면이 복잡하면 "프레스 구역만" 같이 구역별로 나눠 요청하고 여러 번 가져오기 해도 됩니다(코드 기준 갱신이라 중복되지 않음).
- 설비 코드는 회사 설비 코드 체계가 있으면 프롬프트에 예시를 넣어 그 규칙을 따르게 합니다.
- 담당자(manager)는 사용자 이름과 같아야 담당자 호출 알림이 가므로, 가져온 뒤 콘솔에서 지정합니다.
- 도면 자체를 깔끔한 평면도 이미지로 다시 그리게 하는 것(이미지 생성)은 정확도가 낮으므로 권하지 않습니다. 원본 도면을 그대로 배경으로 쓰세요.

## 4. API (자동화할 때)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/admin/layout` | 현재 배치 JSON |
| POST | `/api/admin/layout` | JSON 가져오기 (본문 = 위 스키마) |
| GET/PUT/DELETE | `/api/admin/floorplan` | 평면도 설정 조회/수정(opacity, showInGame, rect)/제거 |
| POST | `/api/admin/floorplan?name=<파일명>` | 평면도 업로드 (본문 = 이미지 바이너리) |
| GET | `/api/floorplan/image?token=<JWT>` | 평면도 이미지 (로그인 사용자) |

모두 `X-Auth-Token` 헤더에 관리자 JWT가 필요합니다. 사내 스크립트나 Claude Code 같은 도구가 도면 폴더를 감시해 자동으로 올리는 식으로 확장할 수 있습니다.
